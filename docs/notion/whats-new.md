> 작성자: 엔지니어링팀 · 버전: ax v1.21.0 (2026-09-02) · 문의: 엔지니어링팀  
> **매 릴리즈마다 이 문서 한 개가 갱신된다.** 팀원이 지금 업데이트해야 하는 이유와 방법만 담는다. 전체 변경 이력은 저장소 `CHANGELOG.md`, 종합 안내는 **ax — 설치·운영·릴리즈 종합 안내** 참고.

## 지금 할 일

```bash
claude plugin marketplace update ax-harness && claude plugin update ax@ax-harness
/ax:doctor      # 사업 폴더에서 1회 — additive 마이그레이션 자동 적용
```

**재init(`/ax:init`)은 필요 없다.** `doctor` 가 없는 키만 추가하는 방식으로 기존 사업 설정을 최신화한다.

### 세션 연속성이 왜 필요했나

팀원이 **각자의 Claude 계정**으로 **서로 다른 머신**에서 같은 사업 저장소를 작업한다. git 은 동기화되지만 Claude Code 의 맥락은 이어지지 않아, 새 세션은 매번 백지에서 시작했다.

세션 기록(transcript) 자체를 공유하는 길은 없다 — 저장 경로에 계정 slug·uuid 가 박히고 세션당 1~12MB 다. 이어져야 할 것은 대화 원문이 아니라 **결정·미해결·일정**이고, 그것은 이미 저장소에 있다(21개 사업 전부 보유). 이 릴리즈는 그것을 **읽히게** 만든다.

훅은 다음 세 가지를 지킨다.

- **세션 시작을 막지 않는다** — 무슨 일이 있어도 통과한다
- **네트워크를 타지 않는다** — 전부 로컬 파일 + `git log`
- **말할 게 없으면 침묵한다** — 빈 머리글이 매 세션 뜨면 사람이 무시하는 법을 배운다

## 주의사항

- **기존 Notion 게시본에는 소급되지 않는다.** 소제목 수정은 앞으로의 게시에만 적용된다. 이미 올라간 문서는 다시 게시해야 반영된다.
- **`/ax:doctor` 를 한 번도 돌리지 않으면 개선이 닿지 않는다.** 사업 폴더마다 1회 필요하다.
- **zip 설치본은 자동 업데이트가 안 된다.** 새 zip 을 다시 풀거나 git-url 방식으로 재등록해야 한다.

## 검토 기록

이번 회차의 `sanitize.py`·`structure_gate.py` 는 외부 스킬(im-not-ai) 적용을 검토하다 건진 부품이다. **자동 윤문 자체는 도입하지 않았다** — 실측 결과 우리 개조식 산출물과 장르가 맞지 않았다. 판단 근거는 **im-not-ai 적용 판정** 문서 참고.

## 약점·한계 (정직)

- **세션 연속성 훅의 실사용 동작은 아직 검증되지 않았다.** 새 세션에서만 발동하므로, 다음 세션 시작 시 맥락 주입이 실제로 뜨는지 확인이 필요하다. 자동 테스트 23건은 통과 상태다.
- **주입분은 매 세션 컨텍스트를 차지한다.** 상한을 두고 있으나 긴 사업일수록 요약이 거칠어진다.
- **이 문서는 사람이 갱신한다.** 릴리즈마다 자동으로 최신화되는 장치는 없다.
