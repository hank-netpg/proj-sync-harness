# im-not-ai 적용 판정 — AI 문체 윤문 스킬을 산출물에 쓸 것인가 (v1.20.0)

> 작성자: 엔지니어링팀 · 버전: ax v1.20.0 (2026-08-28) · 문의: 엔지니어링팀  
> AI 가 쓴 한글을 사람 글처럼 윤문해주는 Claude 스킬을 제안서·주간보고·회의록에 적용할지 검토한 기록. **자동 윤문은 도입하지 않기로** 했고, 검토 과정에서 실제 게시 결함 하나를 찾아 고쳤다.

## 결론

| 판정 | 대상 | 근거 |
|---|---|---|
| **미채택** | 자동 윤문 오케스트레이터 | 우리 산출물에서 고칠 것은 거의 없고, 부술 구조가 8배 많다 |
| **채택** | 부품 3개 | 보이지 않는 문자 제거 · 구조 보존 게이트 · 작성 규칙 1건 |

검토 대상: [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai) — MIT, ★5,045, 10대 카테고리 71개 AI 티 패턴.

## 1. 실측 — 우리 산출물 401파일을 직접 쟀다

| 문서군 | 파일 | 어절 | 길이(중앙값) |
|---|---|---|---|
| 제안서 본문 `proposal/pages/*.md` | 370 | 114,412 | 1,411자 |
| 회의록 | 26 | 20,713 | 1,226자 |
| 주간보고 `reports/주간보고_*.md` | 5 | 1,205 | 861자 |
| **합계** | **401** | **136,330** | |

집계값만 산출했고 본문은 인용하지 않았다.

### 찾으려던 AI 문체가 거의 없었다

제안서 본문 114,412어절 기준.

| 검사 항목 | 건수 | /1,000어절 |
|---|---|---|
| 결산 lexicon — "결론적으로"·"요약하면" | 0 | 0.00 |
| 의의 과장 — "시사하는 바가 크다" | 0 | 0.00 |
| hype 어휘 — "혁신적"·"획기적"·"압도적" | 0 | 0.00 |
| 이중 피동 — "판단되어진다" | 0 | 0.00 |
| 추측 종결 — "~로 보인다"·"~로 판단된다" | 0 | 0.00 |
| 균형 lexicon — "양쪽 모두"·"신중하게" | 0 | 0.00 |
| 문두 접속사 — "또한"·"따라서" | 0 | 0.00 |
| 이중 조사 — "~에서의"·"~으로의" | 0 | 0.00 |
| **"~적 N" 추상 체인** — "전략적 함의"·"실천적 기반" | **228** | **1.99** |

산문이 전체의 62.3% 라 규칙이 작용할 표면은 충분했다(불릿 29.5% · 표 8.1%). 그런데도 0건이라는 것은 **이미 깨끗하다**는 뜻이다.

### 반대로 윤문이 부술 구조는 2,026건

| 항목 | 건수 |
|---|---|
| 연속 불릿 3+ 블록 (규칙 C-2) | 868 |
| 볼드 (규칙 J-1) | 1,060 |
| 명사구 종결 불릿 (규칙 A-13) | 98 |

**고칠 것 248건 대 부술 구조 2,026건 — 약 1 : 8.** 자동 윤문의 기대 수익이 음수다.

### 역치가 우리 문서 길이에 도달하지 않는다

레포 자신이 `scripts/build_calibration.py` 서문에 적어 둔 실측이다.

> "택소노미의 횟수 역치는 문서 길이에 무관한 절대 횟수다. 900자 칼럼에서는 영원히 발동하지 않고, 9,000자 보고서에서는 한 번 걸리면 과잉 발동한다."

| 규칙 | 역치 도달 최소길이 | 제안서 page 도달률 |
|---|---|---|
| I-4 당위 결말 | 1,560자 | 130 / 370 (35.1%) |
| F-5 추상 체인 | 1,771자 | 94 / 370 (25.4%) |
| C-8 부정 대구 | 2,428자 | 42 / 370 (11.4%) |

제안서 page 중앙값이 1,411자다. **64.9% 는 구조적으로 발동조차 하지 않는다** — 측정된 0건이 우연이 아니라 설계상 예측되는 값이다.

## 2. 부적합 사유 — 도구 문제가 아니라 장르가 다르다

그 스킬의 규칙은 **칼럼·에세이**용이다. 우리 산출물은 **개조식**이고, 아래 네 규칙은 형식 요건을 그대로 깬다.

| 규칙 | 처방 | 우리 산출물에서 |
|---|---|---|
| C-2 | 3개 이상 연속 불릿 → 산문으로 통합 | 개조식의 본체가 사라진다 |
| C-4 | 문단 첫 문장 요약 공식 → 사례·인용으로 시작 | 두괄식이 해체된다 |
| A-13 | 명사 나열 → 조사 복원 | 불릿 항목이 문장이 된다 |
| G-1 | 추측 종결 → 단언 | 근거 없는 단정을 만든다 |

같은 이유로 그쪽 기준선(`baseline.json`)에도 `report` 장르가 없다. 우리 문서를 넣으면 `essay` 기준으로 폴백해 점수를 낸다(`metrics.py:230` — `baseline_genre_null:report->essay`). `baseline_v2.json` 은 70개 셀 전부 `_placeholder: true` 다.

규칙 71개 중 22개는 문서 전체를 봐야 판정되는 strict 전용이라 요약 룰북에 노출되지 않는다. 위 네 건도 그 안에 있었다.

## 3. 실제로 채택한 것

| 가져온 것 | 원본 | 반영 위치 |
|---|---|---|
| 제로폭·BOM·bidi 제어문자 제거 | `scripts/sanitize_text.py` | `plugin/ax/scripts/lib/sanitize.py` |
| 결정론 게이트 설계·실패코드 명명 | `scripts/checks.py` | `plugin/ax/scripts/lib/structure_gate.py` |
| 규칙 F-5 "~적 N" 회피 | `ai-tell-taxonomy.md` | `plugin/ax/skills/draft/prompt.md` |

- **NFD→NFC 정규화는 가져오지 않았다.** 이미 `slack_download.sh`·`gdrive_sync.sh`(·구 `notion_normalize.sh`, v1.21.0 삭제) 에 있다. 중복 구현은 어긋날 때 어느 쪽이 맞는지 알 수 없게 만든다.
- **`checks.py` 를 전량 옮기지 않았다.** 원본은 윤문 전후 대조용이라 `하였_injection`·`colloquial_erased` 같은 문체 축이 절반인데, 이 경로는 문체를 건드리지 않으므로 영원히 0이다. 검사가 아무것도 잡지 못하면 통과가 통과라는 뜻을 잃는다.
- 라이선스(MIT) 고지는 저장소 `NOTICE` 에 있다.

### 두고 온 것

- **자동 윤문 전체** — 확정 산출물을 비결정적으로 재작성하는 것은 평가위원 제출물에 맞지 않는다
- **구조·시각 규칙**(C-2·C-9·J-1·J-2) — 불릿·볼드·번호를 걷어내면 개조식이 아니게 된다
- **완곡 표현 제거**(A-10·G-1~G-3) — "검증 필요"를 단정으로 바꾸는 방향이라 근거 원칙과 충돌한다
- **어휘 금지 목록 일괄 도입** — 실측 0건인 표현을 금지해도 프롬프트만 길어진다
- **`report` 기준선 보정** — pre-2022 보고서 대조 코퍼스 구축 비용이 크고, 탐지 대상이 0에 가까워 기대 수익이 낮다

## 4. 부수 성과 — 검토하다 실제 결함을 찾았다

구조 보존 개념을 우리 Notion 게시 경로에 겨눠 보다가, **4단 이하 소제목이 제목으로 올라가지 않고 있었다**는 것을 발견했다. `md_to_notion.py` 의 헤딩 정규식이 `#{1,3}` 이라 `####` 이상은 헤딩으로 인식조차 되지 않고 문단으로 떨어졌다.

| 지표 | 값 |
|---|---|
| 영향받은 제안서 파일 | 168 / 370 |
| 소실된 헤딩 | 368 / 1,406 (26.2%) |
| 수정 후 재측정 | 0% |

Notion 은 `heading_1~3` 만 있으므로 h4 이상은 `heading_3` 으로 접는다. 계층 한 단계는 잃지만 제목이라는 사실은 지킨다 — 문단으로 떨어뜨리는 쪽이 손실이 크다.

**기존 게시본에는 소급되지 않는다.** 해당 문서를 다시 게시해야 반영된다.

## 5. 자기 정정 기록

초기 계산에서 규칙 J-4(괄호 부연)를 **4,912건**으로 보고했으나 과대계상이었다. taxonomy 의 J-4 표적은 `(이는 ~을 의미한다)` 형 부연인데, 정규식이 모든 괄호를 셌다. 5,356건을 분류하면:

| 유형 | 건수 | 비율 |
|---|---|---|
| 기타 짧은 삽입 | 3,060 | 57.1% |
| 영문·약어 병기 | 1,330 | 24.8% |
| 수치·날짜·출처 | 966 | 18.0% |
| **J-4 실제 표적(부연)** | **0** | **0.0%** |

**J-4 의 노출은 0이다.** 다만 처방 문구가 정의보다 넓다 — "괄호 부연 **대부분** 본문화 또는 삭제". LLM 이 이 한 줄만 보고 실행하면 약어 병기와 출처 표기를 걷어낼 수 있다. **노출 리스크가 아니라 과잉적용 리스크**로 재분류한다.

## 약점·한계 (정직)

- **검사에 쓴 정규식은 그 스킬의 자체 탐지기가 아니다.** taxonomy 정의를 옮긴 근사치이며, 특히 A-13·C-2 는 프록시다. 방향은 확실하나 절대 건수에는 오차가 있다.
- **회의록·주간보고 표본이 작다**(26·5 파일). 제안서 370파일 결론에 비해 잠정적이다.
- **`reference/drafts/**/*.md` 635파일은 측정하지 않았다.** 작업 초안이라 산출물 확정본과 성격이 다르다.
- **F-5 지침의 효과는 사후 측정으로만 확인된다.** 기준선 228건 / 1.99per1k 를 기록해 뒀고, 다음 생성분을 재측정해야 안다.
- **파생 코드는 upstream 갱신을 자동으로 따라가지 않는다.** 원본이 고쳐지면 `NOTICE` 의 범위만 수동으로 대조해야 한다.
