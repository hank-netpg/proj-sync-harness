## A1 — 4-스택 SSOT

**전제.** 사업 자료는 성격이 다른 네 곳에 나뉘어 살고, **각각이 자기 영역의 유일한 원본**이다.
한 자료가 두 곳에서 원본 행세를 하면 어느 쪽이 맞는지 판정할 방법이 없어진다.

| 스택 | 담당 | 근거 |
|---|---|---|
| **GitHub** | 텍스트 SSOT — `.md`·소스코드 | `github_push.sh` 가 사무파일 확장자를 `.gitignore` 로 밀어낸다 |
| **대용량 저장소** | 사무파일 SSOT — hwp·doc·ppt·xls·pdf | `config.github.office_exts` 가 경계를 정의한다 |
| **Notion** | **게시본**(원본 아님) — 문서함 DB | `notion_plan.py`(MCP 계획기)가 `출처경로` 로 파일↔페이지를 잇는다 |
| **Slack** | 유입 진입점 — 원본이 들어오는 곳 | `slack_download.sh` → `slack-files/` |

**흔들면.** Notion 을 원본처럼 편집하면 다음 `publish-set` 이 파일 내용으로 덮어쓴다.
게시본은 **파생물**이라는 것이 이 원칙의 실질이다.

○ **판별법** — 어떤 자료를 손으로 고칠 때 「이걸 고치면 다음 동기화가 되돌리는가?」를 물어라.
되돌린다면 거기는 원본이 아니다.

## A2 — 하이브리드 SSOT (텍스트는 git · 대용량은 별도 · 납품본은 예외)

**전제.** A1 의 경계를 실무에서 운용하는 규칙이다.

- **텍스트는 전부 git.** 변경 이력·diff·리뷰가 형상관리의 실체이기 때문이다
  (`manage-config` 스킬이 git commit/diff 를 형상관리 엔진으로 삼는 근거).
- **대용량 사무파일은 git 밖.** 이력이 의미 없고 저장소만 부풀린다.
- **단 `deliverables/`(납품 Archive)는 예외 — 사무파일까지 전부 git.**
  납품본은 「그때 무엇을 냈는가」가 곧 증거라, 이력이 반드시 필요하다
  (`docs/ARCHITECTURE.md` §5 폴더 트리에 `A2 예외`로 표기돼 있다).

**흔들면.** 예외를 잊고 `deliverables/` 를 대용량 저장소로 밀면, 납품 시점의 증거가
버전 없는 파일 하나로 남는다. 분쟁 시 되짚을 수 없다.

## A6 — 환경 동질성 (팀원 PC 에서 똑같이 돈다)

**전제.** 도구는 **팀원 아무 PC 에서나 같은 결과**를 내야 한다. 특정 머신·서버·GPU 에
의존하는 순간, 그 자원을 못 쓰는 사람에게는 도구가 없는 것과 같다.

**구현.**
- **stdlib 우선** — 셸 + Python 표준 라이브러리 + `curl`/`jq`/`gh`. `lib/config.sh` 가
  `python3`/`python` 을 모두 탐색하고 Homebrew 경로를 보강하며 Windows Git Bash 분기를 둔다
- **GPU 없음** — 자체 EXAONE/Polaris/KURE 대신 Claude 서브에이전트 + 로컬 파서
  (`ARCHITECTURE.md` §3 「GPU → Claude Code」)
- **RAG 없음** — 임베딩·벡터DB 대신 `docquark` 지식맵의 target-jump. 벡터DB 를 세우면
  그것을 세운 사람만 쓸 수 있다
- **명시적 분기** — 파서·pptx 빌더는 의존이 필요하다(Node.js 18+·python-pptx·PyYAML·lxml).
  이 예외는 숨기지 않고 `/ax:doctor` §5.5 가 **프리플라이트로 드러낸다**

**흔들면.** 「내 PC 에서는 된다」가 시작된다. 그 시점에 도구는 팀 자산이 아니라 개인 스크립트가 된다.

○ **판별법** — 새 의존을 들일 때 「팀원이 이걸 설치하지 않으면 무엇이 안 되는가, 그리고
그 사실을 **doctor 가 말해주는가**」를 물어라. 말해주지 못하면 A6 위반이다.

## A7 — ax-harness 인증경계

**전제.** **접근 통제의 단위는 `ax-harness` GitHub org 멤버십 하나**다. 도구는 별도의 계정·비밀번호
체계를 만들지 않는다. 하나면 관리되고, 둘이면 어긋난다.

**구현.**
- **토큰은 배포본에 없다.** private secrets repo(`<your-org>/proj-sync-secrets`)에만 있고,
  `ps_fetch_team_token`(`lib/config.sh`)이 `gh` 인증으로 꺼내 전역 캐시에 둔다.
  org 멤버가 아니면 조회 자체가 실패한다 — 이것이 경계다
- **해석 순서**: `.env`/환경변수 → 전역 캐시(`~/.proj-sync/credentials`) → secrets repo 자동 조회
- **registry 교차집계**도 같은 경계 위에 선다 — Leader 가 전 사업을 조망할 수 있는 근거가
  org 멤버십이다(`AX_ORCHESTRATION_DESIGN.md:115`·`AX_ORCHESTRATION_SPEC.md:203`)
- 토큰이 커밋·채널로 새지 않도록 `github_push.sh` 의 secret-scan 이 `xoxb-`·`ghp_`·`ntn_`·
  `secret_` 패턴을 **push 전에 차단**한다

**흔들면.** 토큰을 저장소나 문서에 적는 순간 경계가 org 멤버십이 아니라 「그 문서를 본 사람」이
된다. 되돌릴 수 없다 — 유출된 토큰은 회수가 아니라 재발급 대상이다.

○ **파생 원칙 B1** — 「1 사업 = 1 폴더 = 1 repo」. 사업 단위가 repo 단위와 일치해야
org 멤버십·repo 권한이 곧 사업 접근권이 된다. 한 repo 에 여러 사업을 담으면 A7 이 무너진다.

그 파일이 저장소에 없었다. `AX_ORCHESTRATION_DESIGN.md:5` 도 같은 문서를 "준용한다"고만 쓰고
본문을 담지 않았다. 결과적으로 **네 원칙은 이름과 괄호 안 한 줄이 전부**였고,
코드는 `A6`·`A7` 을 근거로 인용하는데 그 근거를 어디서도 읽을 수 없었다.

그 사실을 문서 머리에 명시했다.
