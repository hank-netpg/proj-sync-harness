# 산출물 문서 구조 감사 (트리분해)

문서를 **헤딩 스택 경로**로 정규화한다. 경로가 diff 키가 되므로 문서군을 집합 연산으로 다룰 수 있다.

```
"5. 기능별 데이터 보고서 > 5.1 4축분석 > [표1]"
```

원래 hwpx·docx 대조분석용으로 만든 기법(`doc_tree.py`, 2026-07-28 `proj-gamma`)을
마크다운·산출물 전반으로 확장했다.

## 언제 쓰나

- 산출물이 수십 건 이상 쌓여 **무엇이 정본인지 흐려졌을 때**
- 아카이브 대상을 고를 때 — 「오래됨」만으로는 못 자른다. 참조·중복까지 봐야 한다
- 문서 저장소를 이관·통합한 직후 정합 점검
- 발주처 제출 전 산출물 체계 점검

## 절차

### 1. 감사 실행

```bash
# 작업 초안 (manage-deliverable 표준 경로)
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/doc_audit.py reference/drafts --json /tmp/audit.json
# 납품 최종본 · 기술문서 계열
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/doc_audit.py deliverables
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/doc_audit.py docs --min-jaccard 0.3
# 저장소 전체를 한 번에 — 초안↔최종본 어긋남이 겹침으로 드러난다
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/doc_audit.py . --min-jaccard 0.5
```

형식별 파서가 자동 분기한다 — `.md` → `doc_tree_md.py` · `.hwpx`/`.docx` → `doc_tree.py`.

### 2. 판정 항목 해석

| 항목 | 뜻 | 조치 |
|---|---|---|
| **완전 동일**(sha1 일치) | 같은 파일이 두 경로에 | 정본 1개만 남기고 제거. 어느 쪽이 정본인지 **참조 그래프로 판정** |
| **겹침 J≥0.7** | 사실상 같은 문서의 다른 판 | 통합 또는 상하위 관계로 재배치 |
| **겹침 J 0.3~0.7** | 주제 중복 | 공통부를 상위 문서로 올리고 하위는 차이만 |
| **H1 복수** | 문서 하나에 제목 여러 개 | 분할하거나 H1 을 하나로 |
| **레벨 건너뜀** | H2 → H4 식 점프 | 중간 레벨 보충 |
| **빈껍데기** | 헤딩만 있고 본문 부족 | 작성 미완 — 산출물 완성도에 반영 |
| **비대**(heading 100+) | 한 문서가 과대 | 장 단위 분절 후보 |

### 3. 아카이브 판정 — 3축을 모두 볼 것

**날짜만으로 자르지 않는다.** 오래됐어도 다른 문서가 참조하면 살아 있는 문서다.

1. **최종수정일** — git 이력 기준(파일 mtime 아님. clone 하면 전부 오늘이 된다)
2. **inbound 참조 수** — `[[문서명]]`·경로 링크를 세어 0 인 것만 후보
3. **중복 여부** — 완전 동일·고Jaccard 는 날짜와 무관하게 정리 대상

세 축을 모두 만족(오래됨 + 참조 0 + 대체본 존재)할 때만 아카이브한다.

### 4. 반영

- **git**: `reference/drafts/99_아카이브/` 로 이동(삭제 금지 — 이력 보존)
- **Notion**: 게시에서 **빼지 않는다.** 빼면 문서함에서 사라져 관리 대상에서 누락된다.
  `notion_plan.py`(MCP 계획기)가 경로로 판정해 `상태`=`아카이브`를 붙이고 **프로젝트 태그는 그대로 둔다** —
  사업별 뷰에 계속 잡히면서 현행 문서와 구분된다. 상위 항목은 기존 계층을 덮어쓰지 않는다.
- 원본 파일이 사라진 게시본은 notion-publish 스킬의 **고아 스윕**(계획의 `orphans[]`)이 `상태`=`아카이브`로
  표시한다(삭제하지 않는다 — 한 번 만들어진 문서는 아카이브 형태로 보관).
- 이동 내역을 커밋 메시지에 **사유와 함께** 남긴다(무엇으로 대체됐는지)

### 5. 보고

개조식으로 — 판정 건수 → 조치 대상 → 사용자 확인 필요 항목 순. 추측 금지, 근거는 경로·해시·참조수로 제시.

## 주의

- **파일 mtime 을 최종수정일로 쓰지 말 것.** clone 직후엔 전부 같은 날짜다. `git log --name-only` 로 파일별 최종 커밋일을 뽑는다
- **Notion `last_edited_time` 도 신뢰하지 말 것.** 속성 일괄 변경(태그 정리 등)이 전건을 덮어쓴다. 그럴 땐 `created_time` 과 git 이력을 쓴다
- 한글 파일명 저장소에서 **`git add -A` 금지** — macOS NFD/NFC 로 같은 파일이 중복 등재된다. 경로를 명시해 add 하고 커밋 후 정규화 중복을 검사한다
- 아카이브는 **이동**이지 삭제가 아니다
