# 위험관리 (Risk Management) — Agile 반복 점검

전자정부 4대 관리 중 **위험관리**를 담당. PM 에이전트가 호출하는 전문 스킬. 방법론: **Agile**(스프린트마다 리스크 재평가).

## 입력 (근거)
- `reference/management/risk/위험관리대장.md` (없으면 초안 생성 제안).
- `.proj-sync/config.json` 의 `wbs.tasks[]` (지연·미할당 → 위험 신호).
- `reference/drafts/10_착수/위험관리계획서.md` (**착수 단계 표준 산출물**, 있으면).
  - ⚠️ 계획서는 관리 문서가 아니라 **산출물**이다 — 별표2 등재·단계 귀속·제출물.
    `management/risk/` 에 두는 것은 **대장**(계속 갱신하는 기록)뿐이다.

## 위험관리대장 표준 항목 (별표2 기반)
| 항목 | 설명 |
|------|------|
| ID | RISK-01 … |
| 위험내용 | 무엇이 위험한가 |
| 발생확률 | 상/중/하 |
| 영향도 | 상/중/하 |
| 등급 | 확률×영향 (상상=최우선) |
| 대응방안 | 회피/전가/완화/수용 |
| 대응상태 | 미대응/대응중/해소 |
| 담당 | owner |
| 갱신일 | 최근 점검일 |

## 점검 절차 (Agile 반복)
1. 위험관리대장을 읽는다. 없으면 표준 항목으로 초안 생성을 PL에 위임 제안.
2. **자동 위험 신호 탐지** (config 근거, 결정론적):
   - 지연 task (`status≠완료 AND due<오늘`) → 일정 위험.
   - owner 미할당 task → 책임 공백 위험.
   - V-Model 짝 누락(설계 완료·테스트 미작성) → 품질 위험.
3. 각 위험의 **등급(확률×영향)** 으로 정렬. 최우선(상·상)부터.
4. **미대응·고등급** 위험을 우선 보고. 대응방안이 없으면 제시.
5. 결과는 PM에게 반환(PM이 종합). 직접 사용자에게 길게 늘어놓지 않는다.

## 출력
- 고위험 Top 3 + 대응상태. 표는 "자세히" 요청 시.
- 근거: "task 1.3 마감 3일 초과 → 일정위험 上" 처럼 셀 수 있는 근거.
- **추측 금지**: 위험 등급은 대장 값 또는 config 파생으로만. 불명확하면 "확인 필요".
